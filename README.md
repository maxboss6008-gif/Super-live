# Super Live International — সোর্স কোড

Original Bengali spec অনুযায়ী বানানো লাইভ-স্ট্রিমিং + ভার্চুয়াল-কয়েন অ্যাপ (অডিও/ভিডিও রুম,
গিফটিং, ওয়ালেট, KYC, মডারেশন, অ্যাডমিন ড্যাশবোর্ড)। মনোরেপো — পাঁচটা স্বাধীনভাবে চালানো
যায় এমন প্যাকেজ।

## ফোল্ডার কাঠামো

```
Super_live_app/
├── package-1-backend/      ব্যাকএন্ড API (NestJS + PostgreSQL + Redis)
│                           → auth/login/2FA, ওয়ালেট, পেমেন্ট, KYC, উইথড্রয়াল,
│                             মডারেশন, মালিকের নিয়ন্ত্রণ (কিল সুইচ ইত্যাদি)
│
├── package-2-realtime/     লাইভ স্ট্রিমিং সার্ভার (Socket.IO + Redis + LiveKit SFU)
│   ├── src/streaming/      → অডিও/ভিডিও রুম (৩০ জন), লক, ব্ল্যাকআউট, চ্যাট, WebRTC
│   └── src/management/     → লাইভ রুমের তালিকা, মডারেটর-প্রবেশের ঘোষণা, কিল-সুইচ সম্প্রচার
│
├── package-3-admin/        অ্যাডমিন ড্যাশবোর্ড (React + Vite, ব্রাউজারে চলে)
│                           → লেনদেন, উইথড্রয়াল অনুমোদন, ফ্রড কেস, সার্ভার নিয়ন্ত্রণ
│
├── package-4-mobile/       মোবাইল অ্যাপ (Expo / React Native)
│                           → লগইন/২FA, ওয়ালেট, অফলাইন ক্যাশ ও সিঙ্ক
│
├── package-5-devops/       CI/CD ডকুমেন্টেশন (আসল ওয়ার্কফ্লো .github/workflows/-এ)
│
├── docs/                   স্থাপত্য/নিরাপত্তা/আইনি ডকুমেন্টেশন (নিচে তালিকা)
│
└── .github/workflows/      CI (typecheck, lint, test, npm audit) + EAS APK বিল্ড
```

## docs/ ফোল্ডারে যা আছে
- **API_CONTRACT.md** — মোবাইল ও অ্যাডমিন ড্যাশবোর্ড ব্যাকএন্ডের কাছ থেকে ঠিক কোন রুট,
  রিকোয়েস্ট ও রেসপন্স আশা করে, তার সম্পূর্ণ তালিকা। ব্যাকএন্ডে কোনো এন্ডপয়েন্ট বদলালে এটাও আপডেট করুন।
- **SECURITY_AUDIT.md** — এখন পর্যন্ত কী নিরাপত্তা-পর্যালোচনা হয়েছে, কী পাওয়া ও ঠিক করা হয়েছে,
  আর কোনগুলো (npm audit, SAST) এখনো বাকি ও কেন।
- **FAULT_TOLERANCE.md** — অফলাইন ক্যাশিং ও সার্ভার-ডাউন সহনশীলতার নকশা।
- **legal/** — Play Store প্রকাশের চেকলিস্ট ও মডারেশন-প্রকাশনার খসড়া (আইনজীবী দিয়ে চূড়ান্ত করাতে হবে)।

## নতুন ডেভেলপার হিসেবে কোথা থেকে শুরু করবেন
প্রতিটা প্যাকেজের নিজস্ব `README.md` আছে (ইনস্টল/চালানোর কমান্ড, env ভেরিয়েবল)। প্রস্তাবিত ক্রম:
1. `package-1-backend` — `docker compose up -d` দিয়ে Postgres/Redis তুলুন, `.env` বসান,
   `npm install && npm run migration:run && npm run start:dev`
2. `package-2-realtime` — `.env`-এ P1-এর সাথে মেলানো `JWT_SECRET`/`SERVICE_TOKEN` দিন, `npm run dev`
3. `package-3-admin` ও `package-4-mobile` — যথাক্রমে `npm run dev` ও `npx expo start`
4. `.github/workflows/` — GitHub-এ পুশ করলে CI নিজে থেকেই চলবে (প্রথমবার EXPO_TOKEN
   সিক্রেট যোগ করলে APK বিল্ডও স্বয়ংক্রিয় হবে)

## বর্তমান অবস্থা (সংক্ষেপে)
আমি যে পরিবেশে এই কোড লিখেছি, সেখানে কোনো নেটওয়ার্ক/Docker/Postgres/Redis ছিল না
(এমনকি `npm install`-ও রেজিস্ট্রিতে পৌঁছাতে না পেরে টাইমআউট হতো), তাই নিজে কখনো এটা
আসল ডাটাবেজের বিপরীতে চালিয়ে দেখতে পারিনি। যা করেছি:
- TypeScript কম্পাইলার দিয়ে পুরো P1/P2-এর টাইপ-চেক (কোনো ভুল পাওয়া যায়নি)
- এনটিটি ⇄ ডাটাবেজ-মাইগ্রেশন কলাম প্রোগ্রাম্যাটিক্যালি মেলানো
- ম্যানুয়াল প্যাটার্ন-ভিত্তিক নিরাপত্তা পর্যালোচনা (`docs/SECURITY_AUDIT.md`)
- `test/e2e/auth.e2e-spec.ts` — পুরো auth ফ্লো (রেজিস্টার → নতুন-ডিভাইস ২FA → wallet →
  লকআউট) আসল Postgres+Redis-এর বিপরীতে চালানোর টেস্ট **লিখে দিয়েছি**, আর
  `.github/workflows/ci.yml`-এ postgres+redis service container বসিয়ে দিয়েছি যাতে
  GitHub-এ push করার সাথে সাথেই (সেখানে আসল নেটওয়ার্ক আছে) এটা স্বয়ংক্রিয়ভাবে সত্যিকারের
  ডাটাবেজের বিপরীতে চলে। এই রানটা আমি নিজে করতে পারিনি — প্রথম push-এর পর Actions ট্যাবে
  "package-1-backend" জব সবুজ হলো কিনা দেখে নিশ্চিত হবেন।
