# Package 5 — DevOps / CI

## এখন যা আছে
`.github/workflows/ci.yml` — প্রতিটি push/PR-এ চারটা প্যাকেজের জন্য আলাদা জব চালায়:
- **typecheck** (`tsc --noEmit`) — P1, P2
- **lint** (ESLint) — চারটা প্যাকেজেই
- **test** (Jest, ফেক Repository/Redis দিয়ে, আসল DB লাগে না) — P1
- **build** (`vite build`, আসল কম্পাইল-লেভেল চেক) — P3
- **npm audit --audit-level=high** — চারটা প্যাকেজেই, যেকোনো high/critical ভালনারেবিলিটি
  পেলে CI ব্যর্থ হবে, মার্জ আটকাবে।

কোনো ধাপ ব্যর্থ হলে GitHub-এ লাল ❌ দেখাবে এবং (সেটিংসে "Require status checks" চালু
করলে) সেই কোড `main`-এ মার্জ হতে দেবে না।

## প্রথমবার যা করতে হবে (আমি করিনি, কারণ GitHub অ্যাকাউন্ট/রিপো দরকার)
1. এই পুরো `Super_live_app` ফোল্ডার একটা GitHub রিপোতে পুশ করুন (`.github/workflows/ci.yml`
   রিপোর রুটে থাকা জরুরি, তাই চারটা প্যাকেজ এক রিপোতে বা একই রুটে রাখুন)।
2. প্রথম push-এর পরই Actions ট্যাবে এই ওয়ার্কফ্লো চলবে। প্রথমবার `npm install` আসল
   `package-lock.json` বানাবে — সেটা কমিট করে রাখুন (`npm ci`-তে বদলাতে চাইলে
   ci.yml-এ `npm install`-কে `npm ci` করে দিন, গতি বাড়বে)।
3. Settings → Branches → Branch protection rule: `main`-এ "Require status checks to
   pass before merging" চালু করে ওপরের ৪টা জব বেছে নিন।

## EAS (মোবাইল APK) বিল্ড — ওয়ার্কফ্লো তৈরি করা আছে, চালু করতে একটা সিক্রেট লাগবে
`.github/workflows/eas-build.yml` ফাইলটা তৈরি করা আছে, `package-4-mobile/**`-এ কিছু
বদলে push হলে বা Actions ট্যাব থেকে ম্যানুয়ালি ("Run workflow") এটা চলবে। এটা আমি
নিজে চালিয়ে দেখতে পারিনি — তার জন্য আপনার Expo অ্যাকাউন্টের টোকেন লাগবে, যা আমার
কাছে নেই এবং থাকা উচিতও না (এটা আপনার অ্যাকাউন্টের ক্রেডেনশিয়াল)।

**চালু করতে আপনাকে যা করতে হবে:**
1. https://expo.dev -এ লগইন করে একটা অ্যাক্সেস টোকেন বানান (Account Settings → Access Tokens)
2. GitHub রিপোর Settings → Secrets and variables → Actions → "New repository secret"
   — নাম `EXPO_TOKEN`, মান ওই টোকেন
3. এরপর `package-4-mobile`-এ কিছু push করলেই (বা Actions ট্যাব থেকে ম্যানুয়ালি চালালে)
   বিল্ড শুরু হবে
4. বিল্ডের অগ্রগতি ও ডাউনলোড লিংক expo.dev ড্যাশবোর্ডে দেখা যাবে — `--no-wait` দেওয়া
   আছে বলে GitHub Actions নিজে বিল্ড শেষ হওয়া পর্যন্ত অপেক্ষা করবে না, শুধু জমা দেবে।

এটাই একমাত্র বাস্তবসম্মত উপায় — এই (বা যেকোনো) চ্যাট কথোপকথনের ভেতর থেকে নিজে একটা
.apk ফাইল কম্পাইল করে দেওয়া সম্ভব না, কারণ তার জন্য Android SDK/Gradle বা Expo-র
ক্লাউড বিল্ড সার্ভিস লাগে, যার কোনোটাতেই এই পরিবেশের সরাসরি প্রবেশাধিকার নেই।

## শুধু মোবাইল ফোন দিয়ে পুরো প্রক্রিয়া চালানো (কম্পিউটার ছাড়া)

টার্মিনাল কমান্ড (`git push`, `eas build`) আসলে ফোন থেকেও চালানো যায় — শুধু "কম্পিউটারের
টার্মিনাল" দরকার না, কোনো একটা জায়গায় লিনাক্স/নোড পরিবেশ দরকার। তিনটা বাস্তব উপায়:

### উপায় ১: GitHub Codespaces (সবচেয়ে সহজ, Android/iPhone দুটোতেই চলে)
এটা ব্রাউজারেই চলে, আলাদা অ্যাপ লাগে না:
1. ফোনের ব্রাউজারে github.com-এ গিয়ে একটা ফ্রি অ্যাকাউন্ট বানান (না থাকলে)
2. নতুন রিপো বানান, এই কোড আপলোড করুন (ছোট ফোল্ডার হলে ব্রাউজারের "Add file → Upload
   files" দিয়ে সরাসরি আপলোড করা যায়; অনেক ফাইল হলে নিচের Codespace থেকে `git clone`+
   `git push` করাই সহজ হবে)
3. রিপোর পেজে সবুজ "Code" বাটন → "Codespaces" ট্যাব → "Create codespace" — এটা ব্রাউজারেই
   একটা পূর্ণাঙ্গ VS Code + টার্মিনাল খুলে দেবে (ফোনের ব্রাউজারেও কাজ করে, যদিও ছোট স্ক্রিনে
   টাইপ করা একটু কষ্টসাধ্য হতে পারে — ব্লুটুথ কিবোর্ড থাকলে সুবিধা হবে)
4. সেই টার্মিনালেই `cd package-4-mobile && npm install -g eas-cli && eas login && eas build ...`
   — ঠিক যেভাবে কম্পিউটারে করতেন, একইভাবে চলবে, কারণ এটা আসলে একটা ক্লাউড লিনাক্স মেশিন

### উপায় ২: Termux (শুধু Android, অ্যাপ হিসেবেই আসল টার্মিনাল)
Termux (F-Droid বা GitHub থেকে — Play Store-এর পুরনো সংস্করণ ভালো কাজ নাও করতে পারে)
ফোনেই আসল লিনাক্স কমান্ড-লাইন দেয়:
```
pkg install nodejs git
git clone <আপনার রিপো URL>
cd Super_live_app/package-4-mobile
npm install -g eas-cli
eas login
eas build -p android --profile preview
```

### উপায় ৩: GitHub-এর নিজস্ব মোবাইল অ্যাপ/ব্রাউজার দিয়ে CI ট্রিগার করা (কোনো টার্মিনালই লাগে না)
কোড একবার GitHub-এ উঠে গেলে, ভবিষ্যতে APK বিল্ড করতে আর কোনো টার্মিনাল লাগবে না:
1. GitHub মোবাইল অ্যাপ বা ব্রাউজারে repo-র **Settings → Secrets and variables → Actions**-এ
   গিয়ে `EXPO_TOKEN` যোগ করুন (টোকেন expo.dev-এও ব্রাউজারে লগইন করে পাওয়া যায়)
2. **Actions** ট্যাবে গিয়ে "EAS — Android APK build" ওয়ার্কফ্লো বেছে নিন → "Run workflow"
   বাটন চাপুন — এটা `.github/workflows/eas-build.yml`-এ `workflow_dispatch` থাকার কারণে
   সম্ভব, যা আগেই যোগ করা আছে
3. বিল্ড GitHub-এর সার্ভারে চলবে, আপনি শুধু বোতাম চাপলেন

## পেশাদার স্ক্যান/টেস্ট টুল — কোনটা CI-তে যোগ করা হয়েছে, কোনটা এখনো বাকি

| টুল | অবস্থা | কী লাগবে আপনার দিক থেকে |
|---|---|---|
| **npm audit** | ✅ ci.yml-এ চালু, প্রতি push-এ | কিছু না, এমনিই চলবে |
| **ESLint** | ✅ ci.yml-এ চালু | কিছু না |
| **SonarCloud** | ✅ job যোগ করা (`sonarcloud` জব), কিন্তু নিষ্ক্রিয় যতক্ষণ না সিক্রেট দেন | sonarcloud.io-এ ফ্রি অ্যাকাউন্ট (পাবলিক রিপোর জন্য ফ্রি), `sonar-project.properties`-এ organization/projectKey বসান, GitHub সিক্রেটে `SONAR_TOKEN` যোগ করুন |
| **Snyk** | ✅ job যোগ করা (`snyk` জব, ৪টা প্যাকেজেই), নিষ্ক্রিয় যতক্ষণ না সিক্রেট দেন | snyk.io-এ ফ্রি অ্যাকাউন্ট, GitHub সিক্রেটে `SNYK_TOKEN` |
| **Appium** (মোবাইল UI অটোমেশন টেস্ট) | ❌ যোগ করা হয়নি | এটা অন্যগুলোর চেয়ে অনেক বড় কাজ — একটা আসল ডিভাইস/এমুলেটর বা ক্লাউড ডিভাইস-ফার্ম (যেমন BrowserStack App Automate, যার ফ্রি ট্রায়াল আছে) লাগবে, আর প্রতিটা স্ক্রিনের জন্য আলাদা টেস্ট স্ক্রিপ্ট লিখতে হবে (লগইন, রুমে ঢোকা, চ্যাট পাঠানো ইত্যাদি)। আপনি BrowserStack বা Sauce Labs-এ একটা অ্যাকাউন্ট (ফ্রি ট্রায়াল) বানালে আমি টেস্ট স্ক্রিপ্ট ও CI wiring লিখে দিতে পারি — কিন্তু এটা একটা আলাদা, বড় কাজ হিসেবে ধরা ভালো, "যোগ করে দিন" বললেই তাৎক্ষণিক হয়ে যাবে না |

**একটা সৎ কথা:** এই চারটা টুল একসাথে চালালেও "ভুলত্রুটি শূন্য" নিশ্চয়তা কেউ দিতে পারে না —
পেশাদার টিমগুলোও পারে না। এগুলো নির্দিষ্ট ধরনের সমস্যা (পরিচিত ভালনারেবিলিটি, কোড-স্মেল,
সাধারণ UI বাগ) ধরতে সাহায্য করে, "নিখুঁত" গ্যারান্টি দেয় না।

## Dependabot (স্বয়ংক্রিয় ডিপেন্ডেন্সি আপডেট) — চাইলে যোগ করুন
আমি এখনো `.github/dependabot.yml` বানাইনি; লাগলে বলুন, চারটা প্যাকেজের জন্য
সাপ্তাহিক npm আপডেট PR বানানোর কনফিগ লিখে দেব।
