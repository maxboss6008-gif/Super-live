# Package 2 – Realtime (দুই প্রধান অংশে ভাগ করা)

## src/streaming/  — লাইভ স্ট্রিমিং ফাইল
অডিও/ভিডিও রুম তৈরি ও যোগদান (সর্বোচ্চ ৩০ জন), লক/আনলক, WebRTC সিগন্যাল রিলে,
প্রটেক্টিভ ব্ল্যাকআউট ইভেন্ট, কয়েন-চার্জড মেসেজিং (আসল কাটাকাটি P1-এ)।
Namespace: /streaming

## src/management/ — ম্যানেজমেন্ট/অ্যাডমিন ড্যাশবোর্ড ফাইল
পপুলার হাব (লাইভ তালিকা), মডারেটর-প্রবেশের প্রকাশ্য ঘোষণা, মাস্টার কিল সুইচ সম্প্রচার।
Namespace: /management (শুধু admin/super_admin/owner রোল সংযুক্ত হতে পারবে)

## সীমাবদ্ধতা
- এই সংস্করণ রুম-স্টেট ইন-মেমরি রাখে (`src/streaming/rooms.ts`)। একাধিক ইনস্ট্যান্সে চালাতে
  এটা Redis হ্যাশ/স্টোরে সরাতে হবে — এই ধাপে করা হয়নি, পরে চাইলে বলুন।
- আসল WebRTC মিডিয়া রাউটিং (SFU, যেমন mediasoup/LiveKit) এখনো বসানো হয়নি; শুধু সিগন্যাল রিলে আছে।
- গোপন/পরিচয়-লুকানো প্রবেশ এখানে নেই — এটা ইচ্ছাকৃত; কারণ আগের বার্তায় আলোচিত হয়েছে।

চালানো: cp .env.example .env (JWT_SECRET অবশ্যই P1-এর সাথে এক) && npm install && npm run dev

## SFU (অডিও/ভিডিও মিডিয়া রাউটিং)
LiveKit ব্যবহার করা হয়েছে (src/streaming/livekit.ts)। .env-এ LIVEKIT_URL/API_KEY/SECRET
না দিলে পুরনো mesh সিগন্যালিং (rtc:signal) চলবে, যা ছোট রুমে (কয়েকজন) ঠিক আছে কিন্তু
৩০ জনের রুমে প্রতিটি ক্লায়েন্টকে ২৯টা সংযোগ রাখতে হবে বলে ব্যবহারযোগ্য না।
LiveKit সেলফ-হোস্ট করতে: https://docs.livekit.io/home/self-hosting/ (Docker Compose দেওয়া আছে ওদের ডকে)।
মোবাইল অ্যাপে livekit-client (বা React Native SDK) দিয়ে room:join থেকে পাওয়া token ও url দিয়ে কানেক্ট করুন।
এটা আমি নিজে চালিয়ে/সংযোগ করে দেখিনি (নেটওয়ার্ক নেই); প্রথমবার আপনার LiveKit সার্ভারের
বিপরীতে টোকেন দিয়ে জয়েন করে দেখুন।
