# সিকিউরিটি/কোয়ালিটি স্ক্যান রিপোর্ট

এই পরিবেশে নেটওয়ার্ক নেই (npm install নিজেই রেজিস্ট্রিতে পৌঁছাতে না পেরে টাইমআউট হয়)।
তাই যা **বাস্তবে চালিয়ে করা হয়েছে** এবং যা **করা যায়নি**, আলাদা করে নিচে দেওয়া হলো —
কোনোটাকেই অন্যটার মতো দেখানো হচ্ছে না।

## ✅ যা সত্যিই চালিয়ে যাচাই করা হয়েছে

**TypeScript কম্পাইলার (আসল SAST না হলেও, বাস্তব টুল দিয়ে বাস্তব চেক):**
`tsc --noEmit` পুরো package-1-backend ও package-2-realtime-এর প্রতিটি ফাইলে চালানো হয়েছে।
node_modules ইনস্টল করা নেই বলে প্রতিটি external প্যাকেজের ইমপোর্টে "Cannot find module"
আসা স্বাভাবিক (ওগুলো বাদ দিয়ে দেখা হয়েছে) — তার বাইরে **কোনো প্রকৃত সিনট্যাক্স বা টাইপ এরর
অবশিষ্ট নেই**। `npm run typecheck` দিয়ে আপনি নিজে `npm install`-এর পর আবার চালিয়ে দেখতে পারবেন।

**এনটিটি ⇄ মাইগ্রেশন কলাম মেলানো (স্ক্রিপ্ট দিয়ে, চোখে দেখে না):**
প্রতিটি `@Entity` ক্লাসের প্রতিটি `@Column` এখন প্রোগ্রাম্যাটিক্যালি মাইগ্রেশনের
`CREATE TABLE`-এর সাথে মিলিয়ে দেখা হয়েছে — ১৬টা টেবিলের সবকটা কলাম মিলেছে।

**প্যাটার্ন-ভিত্তিক ম্যানুয়াল কোড রিভিউ (grep দিয়ে, পুরো কোডবেসে):**
eval/exec, innerHTML/dangerouslySetInnerHTML, হার্ডকোড করা সিক্রেট, রও SQL স্ট্রিং-কনক্যাটেনেশন,
CORS কনফিগারেশন, Math.random()-এর নিরাপত্তা-সংবেদনশীল ব্যবহার, এনটিটি (passwordHash/totpSecret)
রেসপন্সে ফাঁস হচ্ছে কিনা, রেট-লিমিটিং আছে কিনা, JWT এক্সপায়ারি/রিফ্রেশ — এসবের জন্য
সার্চ চালিয়ে দেখা হয়েছে।

### এই রিভিউয়ে পাওয়া ও ঠিক করা আসল সমস্যা
| সমস্যা | ঝুঁকি | সমাধান |
|---|---|---|
| `/auth/*`-এ কোনো রেট-লিমিট ছিল না | ব্রুট-ফোর্স/স্প্যাম রেজিস্ট্রেশন | `@nestjs/throttler`: গ্লোবাল ৬০/মিনিট, auth রুটে ৫–১০/মিনিট-ঘণ্টা |
| অ্যাক্সেস টোকেন ১৫ মিনিট, কোনো রিফ্রেশ টোকেন ছিল না | প্রতি ১৫ মিনিটে পাসওয়ার্ড+২FA দিয়ে আবার লগইন করতে হতো | Redis-ভিত্তিক রোটেটিং রিফ্রেশ টোকেন (৩০ দিন), `/auth/refresh`, `/auth/logout` |
| P2-এর Socket.IO CORS `origin: "*"` | প্রোডাকশনে যেকোনো ওয়েবসাইট সংযোগ নিতে পারত | `ALLOWED_ORIGIN` env দিয়ে নির্দিষ্ট ডোমেইনে সীমিত করার অপশন |
| মোবাইলের deviceId ফলব্যাকে `Math.random()` | দুর্বল র‍্যান্ডমনেস, deviceId নতুন-ডিভাইস-২FA নির্ধারণ করে | `expo-crypto`-র ক্রিপ্টোগ্রাফিকভাবে নিরাপদ র‍্যান্ডম বাইট দিয়ে বদলানো হয়েছে |
| `withdrawals` কন্ট্রোলারে status ফিল্টার মৃত কোড ছিল | ভুল ফলাফল (ভবিষ্যতে) | আগের বার্তায় ঠিক করা হয়েছে |
| `/auth/login` ইত্যাদি আসলে কোনো কোডই ছিল না | পুরো লগইন ফ্লো ভাঙা | আগের বার্তায় পুরো AuthModule বানানো হয়েছে |

### যাচাই করে "সমস্যা না" বলে বাতিল করা হয়েছে এমন কিছু
- মাইগ্রেশনের `DROP TABLE "${t}"` — টেমপ্লেট লিটারেল দেখতে SQL-ইনজেকশনের মতো লাগলেও `t`
  আসে একটা হার্ডকোড করা, ইউজার-ইনপুট-বিহীন তালিকা থেকে — নিরাপদ।
- outbox.js-এর `Math.random()` — এটা শুধু লোকাল কিউ আইটেমের ডুপ্লিকেট-এড়ানো আইডি, সার্ভারে
  নিরাপত্তা/আইডেম্পোটেন্সি কী হিসেবে পাঠানো হয় না — নিরাপত্তা-সংবেদনশীল না।

## ❌ যা করা যায়নি, কেন, আর আপনি কীভাবে করবেন

**ডিপেন্ডেন্সি ভালনারেবিলিটি অডিট (npm audit / Snyk / Dependabot):**
এর জন্য একটা CVE ডাটাবেজের সাথে যোগাযোগ লাগে, যা এই অফলাইন পরিবেশে সম্ভব না। আমি
প্যাকেজ ভার্সন অনুমান করে "এটা নিরাপদ" বলে দাবি করিনি, কারণ ভুল হলে সেটা মিথ্যা
নিশ্চয়তা দেওয়ার মতো হতো। নিজের মেশিনে করুন:
```
cd package-1-backend && npm install && npm audit
cd ../package-2-realtime && npm install && npm audit
cd ../package-3-admin && npm install && npm audit
cd ../package-4-mobile && npm install && npm audit
```
`npm audit fix` দিয়ে যতটা সম্ভব স্বয়ংক্রিয়ভাবে ঠিক হবে; যেগুলো হয় না, সেগুলো ম্যানুয়ালি
ভার্সন আপগ্রেড করে দেখুন।

**আসল SAST টুল (Semgrep, CodeQL ইত্যাদি):**
এগুলোও ইনস্টলের জন্য নেটওয়ার্ক লাগে। CI pipeline-এ (GitHub Actions/GitLab CI) একবার
যোগ করে রাখলে প্রতি commit-এ স্বয়ংক্রিয়ভাবে চলবে — চাইলে package-5-devops-এ এমন একটা
CI কনফিগ লিখে দিতে পারি।

**ESLint/প্রকৃত লিন্টিং:**
একই কারণে চালাতে পারিনি (ইনস্টল করা নেই, নেটওয়ার্ক নেই)। তবে TypeScript কম্পাইলার
(উপরে) অনেকগুলো একই ধরনের ভুল (অব্যবহৃত ভ্যারিয়েবল বাদে) ইতিমধ্যে ধরে ফেলে।

## এখনো যা জানা সীমাবদ্ধতা (নিরাপত্তা না হলেও, উল্লেখযোগ্য)
- JWT_SECRET/SERVICE_TOKEN-এর শক্তি সম্পূর্ণ আপনার env মানের ওপর নির্ভর করে — দীর্ঘ,
  র‍্যান্ডম মান ব্যবহার করুন, কখনো `.env` গিট-এ কমিট করবেন না।
- রেট-লিমিট এখন ইন-মেমরি (@nestjs/throttler-এর ডিফল্ট স্টোরেজ); একাধিক P1 ইনস্ট্যান্স
  চালালে প্রতিটি ইনস্ট্যান্স আলাদাভাবে গুনবে। মাল্টি-ইনস্ট্যান্সে সঠিক গ্লোবাল রেট-লিমিটের জন্য
  `@nestjs/throttler`-এর Redis storage adapter বসাতে হবে — এখনো করিনি, লাগলে বলুন।
